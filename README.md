เว็บสำหรับทีมขายใช้ติดตามลูกค้า CFO / GI / โรงงานใหม่ (กรอ.) / บริษัทจดทะเบียน (SET) ในที่เดียว

**เว็บ:** https://mktwni.github.io/customer_vvb/
**เว็บทดสอบ (UAT):** https://mktwni.github.io/customer_vvb/uat/ (ดูหัวข้อ [เว็บทดสอบ (UAT)](#เว็บทดสอบ-uat))

> ⚠️ เว็บนี้เป็นสาธารณะ ใครมีลิงก์ก็เปิดดูข้อมูลบริษัท เบอร์โทร และอีเมลในเว็บได้

## Sales Tracker

เมนู **Sales Tracker** ด้านซ้าย คือตารางติดตามสถานะการขาย (เดิมคือไฟล์ "Sales Tracker 2569") รวมอยู่ในเว็บนี้แล้ว

- **ส่งลูกค้าเข้าตาราง** ไม่ต้องพิมพ์ซ้ำ: ปุ่ม **ส่งเข้า Sales Tracker** ในหน้าบริษัท, ในแผนติดต่อ (เลือกหลายราย), ในการ์ด "ติดดาว"
  หรือ **+ เพิ่มลูกค้า → ส่งบริษัทที่ติดดาว** — ชื่อ เบอร์ อีเมล และผู้รับผิดชอบกรอกให้เอง
- **เพิ่มลูกค้าที่ไม่มีในทะเบียน** ได้เอง (ปุ่ม **+ เพิ่มลูกค้าใหม่** ในหน้าค้นหา หรือใน Sales Tracker) ระบบเตือนถ้ามีบริษัทชื่อคล้ายกันอยู่แล้ว
- **แนบใบเสนอราคา / ใบแจ้งหนี้** แล้วระบบอ่านยอดเงินให้ (PDF อ่านข้อความ, รูปถ่าย/สแกนใช้ OCR ภาษาไทย อ่านในเบราว์เซอร์ ไม่ส่งไฟล์ไปที่อื่น)
  ยอดจะถูกใช้เป็น Forecast / Actual **หลังจากกดยืนยัน** เท่านั้น และแสดงเครื่องหมาย ✓ ว่ายืนยันด้วยเอกสาร
- ไฟล์แนบเก็บใน Google Drive ของหัวหน้าทีม ผ่านสคริปต์เดียวกับการแชร์ข้อมูลทีม (ดู [`team-sync/README.md`](team-sync/README.md#แนบเอกสาร-ใบเสนอราคา--ใบแจ้งหนี้))
- ย้ายข้อมูลจากไฟล์เดิม: **เพิ่มเติม → นำเข้าจาก Sales Tracker เดิม** (ไฟล์สำรอง JSON หรือ Google Sheet ที่ดาวน์โหลดเป็น CSV / Excel)
  นำเข้าซ้ำได้ ไม่สร้างรายการซ้ำและไม่เขียนทับสิ่งที่ทีมแก้ไว้

## โครงสร้าง

| โฟลเดอร์ | คืออะไร |
| --- | --- |
| `app/` | ตัวเว็บ (React + Vite + TypeScript) — ดูวิธีรันและโครงสร้างโค้ดใน [`app/README.md`](app/README.md) |
| `project/data/` | ไฟล์ข้อมูลที่เว็บใช้ (`gcc.json`, `gcc-certs.json`, `gcc-detail/`, `rounds.json`, …) |
| `project/*.dc.html`, `project/*.js` | ไฟล์ต้นแบบจาก Claude Design (ใช้อ้างอิงหน้าตาและการทำงาน) |
| `.github/workflows/deploy-pages.yml` | build และขึ้นเว็บบน GitHub Pages ทุกครั้งที่ push เข้า `main`: เว็บทดสอบ `/uat/` จาก `main` และเว็บจริงจาก branch `live` |
| `.github/workflows/promote-live.yml` | ปุ่ม **ขึ้นเว็บจริง**: ย้าย `live` ไปรุ่นที่ตรวจบน UAT แล้ว และขึ้นเว็บใหม่ |

ไฟล์ Excel ต้นฉบับ (`project/uploads/`) และบันทึกการคุยออกแบบ (`chats/`) ไม่ได้เก็บไว้ใน repo นี้

## เว็บทดสอบ (UAT)

ทุกอย่างที่แก้ต้องผ่าน UAT ก่อน ตรวจแล้วค่อยขึ้นเว็บจริง

1. merge PR เข้า `main` แล้วรอราว 10 นาที ของใหม่จะขึ้นที่ `/uat/` เท่านั้น เว็บจริงยังเหมือนเดิม
2. ตรวจบน UAT ป้ายมุมขวาล่างบอกรุ่นที่กำลังดู เช่น `รุ่น 59ce67e`
3. ตรวจผ่านแล้ว ไปที่แท็บ **Actions → ขึ้นเว็บจริง (UAT ไปเว็บจริง) → Run workflow**
   ใส่รุ่นจากป้าย UAT หรือเว้นว่างเพื่อเอารุ่นล่าสุดที่ merge แล้ว กด **Run workflow** แล้วรอราว 10 นาที
4. เว็บจริงจะเป็นรุ่นนั้นทั้งหมด รวมทุก PR ที่ merge ก่อนรุ่นนั้น และไม่ต้องย้ายข้อมูลใด ๆ จาก UAT

เว็บจริง build จาก branch `live` ซึ่งขยับได้ทางปุ่มนี้เท่านั้น อย่า push เข้า `live` เอง
ถ้าต้องย้อนเว็บจริง ให้แก้บน `main` ตรวจบน UAT แล้วกดขึ้นเว็บจริงตามปกติ

- UAT build ด้วย `VITE_UAT=1` (ดู `app/src/lib/uat.ts`) ส่วนที่ยังไม่พร้อมขึ้นเว็บจริง เช่น **หน้าแรก** กันไว้ให้เปิดเฉพาะบน UAT
  แม้กดขึ้นเว็บจริงแล้วก็ยังไม่แสดงบนเว็บจริง จนกว่าจะเอาเงื่อนไขนี้ออก
- ข้อมูลที่เบราว์เซอร์เก็บของ UAT ใช้ชื่อแยก (ขึ้นต้นด้วย `uat:`) จึงไม่อ่าน ไม่ทับ และไม่ซิงก์ข้อมูลของเว็บจริงในเครื่องเดียวกัน
- ทุกหน้ามีป้าย "เว็บทดสอบ (UAT)" มุมขวาล่าง และชื่อแท็บขึ้นต้นด้วย UAT
- ทีมของ UAT (หน้าเข้าสู่ระบบของ UAT) คือ `UAT_TEAM_URL` ใน [`app/src/lib/constants.ts`](app/src/lib/constants.ts)
  ลิงก์ Web app ของสคริปต์ทีมชุดทดสอบ ที่ผูกกับ Google Sheet แยกจากของจริง ตั้งตาม[ขั้นตอนทีมใหม่](team-sync/README.md#ขั้นตอน-ทีมใหม่)
  ข้อ 1–6 แล้วส่ง Web app URL ให้ผู้พัฒนาใส่ เมื่อ merge แล้ว UAT จะเปิดที่หน้าเข้าสู่ระบบของทีมทดสอบ (ทำข้อ 7–8 บน UAT)
  ถ้ายังเป็น `''` UAT จะไม่เชื่อมทีม ข้อมูลที่ลองบันทึกอยู่ในเบราว์เซอร์เครื่องนั้นเท่านั้น
- ห้ามใส่ลิงก์สคริปต์ทีมจริงใน `UAT_TEAM_URL` เพราะของที่ลองใน UAT จะเข้าไปอยู่ในข้อมูลจริงของทีม (ชุดทดสอบตรวจให้)
- บัญชีผู้ใช้ของ UAT เป็นคนละชุดกับเว็บจริง สร้างในหน้า **ผู้ใช้และสิทธิ์** ของ UAT

```bash
cd app
npm install
npm run dev     # http://localhost:5173
npm test
```

## อัปเดตข้อมูลบนเว็บ

แก้หรือแทนที่ไฟล์ใน `project/data/` แล้ว push เข้า `main` — ระบบจะ build และขึ้นเว็บใหม่ให้เอง
(การอัปโหลด Excel ในแท็บ "อัปเดตข้อมูล" บนเว็บ จะเก็บไว้ในเบราว์เซอร์เครื่องนั้นเท่านั้น)
