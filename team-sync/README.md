# แชร์ข้อมูลทีมด้วย Google Sheet

ทำครั้งเดียวโดยหัวหน้าทีม ใช้เวลาประมาณ 5 นาที หลังจากนั้นทุกคนในทีมจะเห็น ดาว สถานะการขาย ผู้รับผิดชอบ นัด
บันทึกการติดต่อ เบอร์ที่แก้ รายชื่อทีม และผลตรวจข้อมูลซ้ำ เหมือนกันทุกเครื่อง และได้[การแจ้งเตือนทางอีเมล](#การแจ้งเตือนทางอีเมล)
(ใบเสนอราคารอตรวจ สรุปงวดเงินและนัดหมายทุกเช้าวันทำงาน)

> **ทีมที่ใช้งานอยู่แล้ว: มีอัปเดตสคริปต์ที่ต้องทำครั้งเดียว** ดู[อัปเดตสคริปต์: บทบาทและสิทธิ์ + การแจ้งเตือน](#อัปเดตสคริปต์-บทบาทและสิทธิ์--การแจ้งเตือน)
> (ประมาณ 5–10 นาที ต้องกดอนุญาตสิทธิ์ใหม่ 2 อย่าง **ก่อน** Deploy) และ[อัปเดตสคริปต์: ขั้นตอน 5 ขั้น](#อัปเดตสคริปต์-ขั้นตอน-5-ขั้น) (ทำหลังเว็บอัปเดตแล้ว)

ข้อมูลทีมจะเก็บอยู่ใน Google Sheet ของคุณเอง (ชีตชื่อ `sync`) ส่วนไฟล์แนบ (ใบเสนอราคา / ใบแจ้งหนี้) เก็บในโฟลเดอร์
Google Drive ของคุณ ทั้งชีตและโฟลเดอร์ยังเป็นส่วนตัว คนในทีมไม่ต้องมีสิทธิ์เปิด
เว็บจะคุยกับชีตผ่าน Apps Script และแต่ละคน**เข้าสู่ระบบด้วยบัญชีของตัวเอง** (ชื่อผู้ใช้ + รหัสผ่าน) ที่หัวหน้าทีมสร้างให้
พร้อม[บทบาท](#บทบาทและสิทธิ์) ผู้ดูแลระบบ / พนักงานขาย / ดูอย่างเดียว

**เว็บของบริษัทมีลิงก์ Web app ของทีมฝังไว้แล้ว** เปิดเว็บจะขึ้นหน้าเข้าสู่ระบบของทีมก่อนทุกครั้ง สมาชิกแค่เปิดเว็บแล้วเข้าสู่ระบบ
ไม่ต้องใช้ลิงก์เชิญ และไม่ต้องวางลิงก์อะไร (เครื่องที่เคยเชื่อมต่อด้วยลิงก์เดิมของทีม จะย้ายมาใช้ลิงก์ที่ฝังไว้เองเมื่อเปิดเว็บ
พร้อมรายการที่ค้างส่ง และไม่ต้องเข้าสู่ระบบใหม่)

> ทีมที่ตั้งค่าไว้ก่อนมีบัญชีผู้ใช้ (เชื่อมต่อด้วย **รหัสทีม**) ยังซิงก์ได้ตามเดิม จนกว่าหัวหน้าทีมจะ
> [เปิดใช้บัญชีผู้ใช้](#เปิดใช้บัญชีผู้ใช้-หัวหน้าทีม)

## อัปเดตสคริปต์: ขั้นตอน 5 ขั้น

เว็บรุ่นที่ Sales Tracker มี 5 ขั้น (CONTACT · QUOTATION · FOLLOW · CLOSE · PAY) บันทึกนัดโทรและนัดติดตามที่ CONTACT และ FOLLOW
แทน CALL1, CALL2, FOLLOW1, FOLLOW2 สคริปต์เดิมยังซิงก์ได้ครบทุกอย่าง แต่**อีเมลสรุปวันนี้ (หัวข้อนัดหมาย) จะไม่เห็นนัดที่บันทึกจากเว็บรุ่นนี้**
จนกว่าจะอัปเดตสคริปต์ ข้อมูลเดิมไม่ต้องย้าย ไม่มีอะไรหาย

1. **อัปเดตเว็บก่อนเสมอ** เปิดเว็บแล้วกด F5 ขั้นตอนใน Sales Tracker ต้องเป็น CONTACT · QUOTATION · FOLLOW · CLOSE · PAY แล้ว
   (สคริปต์รุ่นนี้ไม่รับการบันทึกจากเว็บรุ่นก่อน ถ้าวางสคริปต์ก่อนเว็บอัปเดต ทุกคนจะบันทึกไม่ได้จนกว่าเว็บจะอัปเดต)
2. ทำข้อ 1, 2 และ 4 ของ[หัวข้อถัดไป](#อัปเดตสคริปต์-บทบาทและสิทธิ์--การแจ้งเตือน): เก็บบรรทัด `TEAM_KEY` → วางโค้ดใหม่แล้วใส่บรรทัดนั้นกลับ → บันทึก
   → **Deploy → Manage deployments → Edit → Version: New version → Deploy** (ทีมที่เคย Run `setupNotify` แล้วไม่ต้อง Run ใหม่)
3. แท็บที่เปิดค้างไว้ตั้งแต่ก่อนเว็บอัปเดตจะอ่านได้แต่บันทึกไม่ได้ และขึ้น "มีเวอร์ชันใหม่ กรุณารีเฟรชหน้าเว็บ (F5)" ให้กด F5
   สิ่งที่แก้ไว้ยังอยู่และจะส่งต่อให้ (แท็บรุ่นเก่ามองไม่เห็นสิ่งที่บันทึกที่ CONTACT / FOLLOW จึงไม่ให้บันทึกหรือลบทับ)

## อัปเดตสคริปต์: บทบาทและสิทธิ์ + การแจ้งเตือน

อัปเดตครั้งเดียวที่รวมทุกอย่าง: สิทธิ์แยกรายการและบทบาทที่สร้างเองได้ คำขอสิทธิ์ การซ่อนยอดเงินจริงจากบัญชีที่ไม่มีสิทธิ์ดู
การตรวจใบเสนอราคา การแจ้งเตือนทางอีเมล การตรวจรับเงินรายเดือน และค่าใช้จ่ายของงาน (สคริปต์รุ่นนี้รองรับหน้าค่าใช้จ่ายที่จะมาในเว็บรุ่นถัดไปแล้ว
ไม่ต้องอัปเดตสคริปต์อีกรอบ) ทำโดยเจ้าของสคริปต์ (คนที่สร้างไฟล์ Google Sheet ของทีม) ประมาณ 5–10 นาที

**ก่อนเริ่ม** ให้ผู้พัฒนาอัปเดตเว็บก่อน (เว็บเวอร์ชันใหม่ใช้กับสคริปต์เดิมได้ ถ้ายังไม่ได้อัปเดตเว็บ ทีมจะใช้งานได้ตามเดิม
แต่ยังไม่เห็นหน้าตั้งค่าใหม่) และเลือกช่วงที่ไม่มีใครกำลังแก้ข้อมูลมาก ระหว่างทำทุกคนยังซิงก์ได้ตามปกติ

1. **เก็บรหัสทีมเดิมไว้** เปิดไฟล์ Google Sheet ของทีม → **ส่วนขยาย (Extensions) → Apps Script**
   แล้วคัดลอกบรรทัด `const TEAM_KEY = '…';` ทั้งบรรทัดไปวางพักไว้ (เช่นใน Notepad) — ทีมที่ใช้บัญชีผู้ใช้แล้วและบรรทัดนี้เป็น `''` ข้ามได้
2. **วางโค้ดใหม่** ลบโค้ดเดิมใน `Code.gs` ทั้งหมด วางโค้ดจากไฟล์ [`Code.gs`](Code.gs) (กด **Copy raw file**)
   แล้ว**แทนบรรทัด `const TEAM_KEY = '';` ด้วยบรรทัดที่เก็บไว้** → กด **บันทึก** (ไอคอนแผ่นดิสก์)
   - (ไม่บังคับ) ไฟล์ [`appsscript.json`](appsscript.json) บอก Google ว่าสคริปต์ขอสิทธิ์อะไรบ้าง ถ้าไม่วาง Google จะดูจากโค้ดเอง
     และขอสิทธิ์ชุดเดียวกัน ถ้าจะวาง: **ตั้งค่าโปรเจกต์ (Project Settings ⚙)** → ติ๊ก **Show "appsscript.json" manifest file in editor**
     → กลับมาที่ **Editor** → เปิดไฟล์ `appsscript.json` → วางแทนทั้งไฟล์ → **บันทึก**
3. **อนุญาตสิทธิ์ใหม่ (ต้องทำก่อนข้อ 4)** ช่องเลือกฟังก์ชันข้างปุ่ม **Run** ให้เป็น `setupNotify` แล้วกด **Run**
   - Google จะขออนุญาต: **Review permissions** → เลือกบัญชี → **Advanced** → **Go to … (unsafe)** → **Allow**
   - สิทธิ์ใหม่ 2 อย่างคือ **Send email as you** (ส่งอีเมลในนามคุณ — ส่งเฉพาะอีเมลพนักงานที่ยืนยันแล้ว ไม่ส่งถึงลูกค้า)
     และ **Allow this application to run when you are not present** (ทำงานเมื่อคุณไม่ได้เปิดอยู่ — ตรวจทุก 10 นาทีว่ามีงวดเงิน นัดหมาย หรือสรุปประจำวันต้องแจ้ง ส่วนใบเสนอราคาส่งทันทีที่แนบหรือแก้)
   - สำเร็จเมื่อ **Execution log** ขึ้น "การแจ้งเตือนทางอีเมลพร้อมใช้งาน: ใบเสนอราคาส่งทันทีที่แนบหรือแก้ เรื่องอื่น (งวดเงิน นัดหมาย สรุปประจำวัน) ตรวจทุก 10 นาที วันนี้ส่งได้อีก … ฉบับ"
   - `setupNotify` กด Run ซ้ำได้ ไม่มีอะไรซ้ำ (ตั้งเวลาไว้ชุดเดียวเสมอ) และไม่ส่งอีเมลย้อนหลังของข้อมูลที่มีอยู่ก่อน
     ใบเสนอราคาที่แนบก่อนวันนี้ไม่ต้องตรวจ
4. **Deploy เวอร์ชันใหม่** **Deploy → Manage deployments** → กด ✏️ (**Edit**) ที่ deployment เดิม → **Version: New version** → **Deploy**
   - URL เดิมยังใช้ได้ คนในทีมไม่ต้องทำอะไร **อย่ากด New deployment** (จะได้ URL ใหม่ ที่เว็บไม่รู้จัก)
   - **ทำข้อ 3 ก่อนข้อ 4 เสมอ** ถ้า Deploy ไปก่อนกดอนุญาต ทุกเครื่องในทีมจะซิงก์ไม่ได้ (ขึ้นว่าลิงก์ไม่ถูกต้อง
     หรือ Authorization is required) จนกว่าจะกลับไปทำข้อ 3 — กด Run `setupNotify` → **Allow** แล้วจะใช้ได้เองโดยไม่ต้อง Deploy ใหม่
5. **ตั้งค่าในเว็บ** (ผู้ดูแลระบบ) เปิดเว็บแล้วกด F5 หนึ่งครั้ง → **ผู้ใช้และสิทธิ์ → การแจ้งเตือน**
   - การ์ด **ระบบส่งอีเมล** ต้องขึ้นว่า **ทำงานอยู่** แล้วกด **บันทึก** หนึ่งครั้ง (เว็บจะบันทึกที่อยู่เว็บไว้ใช้ทำลิงก์และโลโก้ในอีเมล
     — ก่อนบันทึก อีเมลจะไม่มีปุ่มและลิงก์)
   - ทุกคนใส่อีเมลของตัวเองที่ **การแจ้งเตือนของฉัน** (กดชื่อตัวเองมุมขวาบน) ระบบส่งรหัส 6 หลักไปที่อีเมลนั้น ใส่รหัสภายใน 15 นาที
     แล้วกด **ส่งอีเมลทดสอบ** ถ้าอีเมลไปอยู่ในสแปม ให้กด **ไม่ใช่สแปม** (ผู้ดูแลระบบใส่อีเมลให้ได้ที่บัญชีของแต่ละคน แต่เจ้าตัวต้องใส่รหัสเอง)
6. แท็บที่เปิดค้างไว้ตั้งแต่ก่อนอัปเดตจะขึ้น "มีเวอร์ชันใหม่ กรุณารีเฟรชหน้าเว็บ (F5)" เมื่อบันทึก ให้กด F5 สิ่งที่แก้ไว้ยังอยู่และจะส่งต่อให้

**ถ้าบัญชี Google Workspace ของบริษัทไม่ให้สคริปต์ส่งอีเมล** (ข้อ 3 ขึ้นว่าผู้ดูแลระบบของโดเมนบล็อกไว้) ให้ติดต่อผู้ดูแล Google Workspace
หรือแจ้งผู้พัฒนาเพื่อทำเป็น 2 รอบ: รอบแรกไม่มีส่วนอีเมล (ตรวจใบเสนอราคาในเว็บได้ ไม่ต้องอนุญาตสิทธิ์ใหม่) รอบสองค่อยเพิ่มอีเมล

**ย้อนกลับ** (ใช้เมื่อจำเป็นจริง ๆ) สคริปต์เวอร์ชันก่อนรู้จักแค่ 3 บทบาท ผู้ดูแลระบบ / พนักงานขาย / ดูอย่างเดียว
บัญชีที่อยู่ในบทบาทที่สร้างเอง ถ้าวางโค้ดเก่ากลับไปตรง ๆ จะ**แก้และลบได้ทุกอย่าง** จึงต้องทำตามลำดับนี้:

1. **ก่อนวางโค้ดเก่า** ในโค้ดเวอร์ชันนี้ เลือกฟังก์ชัน `prepareRollback` แล้วกด **Run** — บัญชีในบทบาทที่สร้างเอง
   ย้ายเป็น**พนักงานขาย**ถ้าบทบาทนั้นทำได้ครบอย่างพนักงานขายแบบเดิม (ไม่นับสองข้อของค่าใช้จ่ายของงาน ซึ่งสคริปต์เก่าไม่ได้ซ่อนหรือตรวจอยู่แล้ว)
   ไม่อย่างนั้นเป็น**ดูอย่างเดียว** (รวมบัญชีที่บทบาทชั่วคราว
   หรือบทบาทพนักงานขายที่ถูกแก้ ทำได้น้อยกว่านั้น) และการแจ้งเตือนทางอีเมลหยุด **Execution log** บอกชื่อบัญชีที่ย้าย (ผู้ดูแลระบบไม่ถูกย้าย)
2. วางโค้ดเวอร์ชันก่อนหน้ากลับ แล้ว Deploy → Manage deployments → Edit → New version
3. ถ้าบัญชีที่ถูกย้ายต้องแก้ข้อมูลต่อ ผู้ดูแลระบบเปลี่ยนเป็นพนักงานขายได้ที่ **ผู้ใช้และสิทธิ์** ของเว็บ

หลังย้อนกลับ **ยอดเงิน ค่าคอมมิชชั่น และค่าใช้จ่ายของงานไม่ถูกซ่อนจากบัญชีใดอีก** (ทุกบัญชีเห็นยอดเงินเหมือนก่อนอัปเดต) สิทธิ์เพิ่ม บทบาทชั่วคราว
และการตรวจใบเสนอราคาไม่มีผล บทบาทที่สร้างไว้ คำขอ และอีเมลของทุกคนยังเก็บอยู่ใน Script Properties
เมื่อวางโค้ดเวอร์ชันนี้กลับอีกครั้ง ให้ Run `setupNotify` ก่อน Deploy (ข้อ 3 ของการอัปเดตด้านบน) แล้วตั้งบทบาทของบัญชีที่ถูกย้ายกลับที่ **ผู้ใช้และสิทธิ์**

## ขั้นตอน (ทีมใหม่)

> ถ้าหน้าจอ Apps Script เป็นภาษาไทย ชื่อปุ่มจะเป็นภาษาไทยแต่อยู่ตำแหน่งเดิม: **Run** คือปุ่มรูป ▷ ในแถบด้านบน
> และ **Deploy** คือปุ่มสีน้ำเงินมุมขวาบน (ภาษาไทยประมาณว่า "การทำให้ใช้งานได้") ตัวเลือกในหน้า Deploy ให้เลือก
> **Web app / เว็บแอป**, ทำงานในฐานะ **Me / ฉัน** และผู้มีสิทธิ์เข้าถึง **Anyone / ทุกคน**

1. **สร้างชีต** เปิด <https://sheets.new> แล้วตั้งชื่อ เช่น `GCC ข้อมูลทีม`
2. **เปิด Apps Script** เมนู **ส่วนขยาย (Extensions) → Apps Script**
3. **วางโค้ด** ลบโค้ดเดิมในไฟล์ `Code.gs` ทั้งหมด แล้ววางโค้ดจากไฟล์ [`Code.gs`](Code.gs) ในโฟลเดอร์นี้
   (เปิดไฟล์แล้วกดปุ่ม **Copy raw file** มุมขวาบน)
4. **ไม่ต้องตั้งรหัสทีม** ปล่อยบรรทัด `const TEAM_KEY = '';` ไว้ตามเดิม แล้วกด **บันทึก** (ไอคอนแผ่นดิสก์)
   — ทีมใหม่ใช้บัญชีผู้ใช้ ([แบบรหัสทีมเดิม](#ใช้รหัสทีมแทนบัญชีผู้ใช้-แบบเดิม) ยังทำได้ แต่ไม่แนะนำ)
5. **อนุญาตสิทธิ์และรับรหัสตั้งค่า** ดูช่องเลือกฟังก์ชันข้างปุ่ม **Run** (แถบด้านบน) ให้เป็น `setup` แล้วกด **Run**
   - Google จะขออนุญาต: **Review permissions** → เลือกบัญชี → **Advanced** → **Go to … (unsafe)** → **Allow**
     (ขึ้นคำว่า unsafe เพราะเป็นสคริปต์ที่คุณสร้างเอง ยังไม่ได้ส่งให้ Google ตรวจ
     และจะมีสิทธิ์ Google Drive ด้วย สำหรับเก็บไฟล์แนบ — ดูเหตุผลที่หัวข้อ [แนบเอกสาร](#แนบเอกสาร-ใบเสนอราคา--ใบแจ้งหนี้))
   - Google ขอสิทธิ์ทั้งหมดในครั้งเดียว: ชีตนี้ Google Drive (ไฟล์แนบ) ส่งอีเมลในนามคุณ และทำงานเมื่อคุณไม่ได้เปิดอยู่
     (การแจ้งเตือน ดู[การแจ้งเตือนทางอีเมล](#การแจ้งเตือนทางอีเมล)) — `setup` ตั้งการแจ้งเตือนให้ด้วย ไม่ต้อง Run `setupNotify` อีก
   - ถ้าสำเร็จ กล่อง **Execution log** ด้านล่างจะขึ้น "พร้อมใช้งาน: สร้างชีต "sync" และโฟลเดอร์ … แล้ว",
     "การแจ้งเตือนทางอีเมลพร้อมใช้งาน" และบรรทัด **รหัสตั้งค่าผู้ดูแลระบบ: 1234-5678 (ใช้ได้ครั้งเดียว ภายใน 24 ชั่วโมง)** — คัดลอกรหัสนี้ไว้ใช้ในข้อ 7
     และ**อย่าส่งให้ใคร** (ใครมีรหัสนี้ก็สร้างบัญชีผู้ดูแลระบบได้)
   - ในไฟล์ Google Sheet จะมีแท็บใหม่ชื่อ `sync` ที่แถบล่าง (ถ้ายังไม่เห็น ให้รีเฟรชหน้าชีต)
     และใน Google Drive จะมีโฟลเดอร์ **GCC Sales Tracker — เอกสาร**
   - รหัสหมดอายุหรือหาไม่เจอ: กด **Run** `setup` อีกครั้ง จะได้รหัสใหม่ (รหัสเดิมใช้ไม่ได้ทันที)
6. **เผยแพร่เป็น Web app** กด **Deploy → New deployment** → กดรูปเฟือง ⚙ เลือก **Web app**
   - **Execute as:** `Me`
   - **Who has access:** `Anyone` (ทุกคน — จำเป็น เพื่อให้เว็บเรียกได้ แต่ข้อมูลทีมเปิดได้เฉพาะคนที่เข้าสู่ระบบ)
   - กด **Deploy** แล้ว **คัดลอก Web app URL** (ขึ้นต้นด้วย `https://script.google.com/macros/s/…` และ**ลงท้ายด้วย `/exec`**
     — อย่าใช้ลิงก์ทดสอบที่ลงท้ายด้วย `/dev`)
7. **สร้างบัญชีผู้ดูแลระบบในเว็บ** เปิดเว็บ → หน้า **ทีมนี้ยังไม่ได้เปิดใช้บัญชีผู้ใช้** → **ฉันคือหัวหน้าทีม**
   → หน้า **เปิดใช้บัญชีผู้ใช้ (หัวหน้าทีม)** → ใส่ **รหัสตั้งค่า** จากข้อ 5, **ชื่อที่แสดง** (ชื่อที่ทีมเห็นในข้อมูล เช่น ผู้รับผิดชอบ),
   **ชื่อผู้ใช้** (ภาษาอังกฤษตัวเล็ก ตัวเลข `.` `_` `-` ยาว 3–32 ตัว) และรหัสผ่าน → **สร้างบัญชีผู้ดูแลและเข้าสู่ระบบ**
   - คุณเป็น**ผู้ดูแลระบบ** ข้อมูลที่เคยบันทึกไว้ในเครื่องนี้จะถูกส่งขึ้นชีตด้วย
   - เว็บคุยกับลิงก์ที่ฝังไว้ในเว็บเท่านั้น ทีมใหม่ (ได้ Web app URL ใหม่ในข้อ 6) ให้ส่ง URL นั้นให้ผู้พัฒนาใส่ในเว็บก่อน
     (เว็บที่ไม่มีลิงก์ฝังไว้ เช่นตอนพัฒนา: แท็บ **อัปเดตข้อมูล** → การ์ด **แชร์ข้อมูลทีม** → วาง URL → **ถัดไป**)
8. **สร้างบัญชีให้ทีม** หน้า **ผู้ใช้และสิทธิ์** → **+ เพิ่มผู้ใช้** → ชื่อที่แสดง ชื่อผู้ใช้ และบทบาท → **สร้างบัญชี**
   - เว็บจะสร้าง**รหัสผ่านชั่วคราว**ให้ กด **คัดลอกข้อความเชิญ** (มีลิงก์เว็บ ชื่อผู้ใช้ และรหัสผ่านชั่วคราว)
     แล้วส่งให้เจ้าตัว**ทางแชตส่วนตัว ไม่ใช่ในกลุ่ม** — รหัสผ่านชั่วคราวแสดงครั้งเดียว
   - เพื่อนเปิดเว็บ → เข้าสู่ระบบด้วยรหัสผ่านชั่วคราว → ตั้งรหัสผ่านของตัวเอง (ข้อมูลที่เขาบันทึกไว้ในเครื่องก่อนหน้าจะถูกรวมเข้ามาด้วย)
   - หน้าเข้าสู่ระบบจะขึ้น **ทีม …XXXXXXXXXX** (ท้าย URL ของ Web app) ให้เข้าสู่ระบบเฉพาะลิงก์ที่ได้จากหัวหน้าทีมโดยตรง
     ถ้าได้ลิงก์มาทางอื่น ให้เทียบรหัสนี้กับหัวหน้าทีมก่อน ถ้าไม่ตรงกัน อย่าใส่รหัสผ่าน
   - แนะนำให้มี**ผู้ดูแลระบบอย่างน้อย 2 คน** เผื่อคนหนึ่งลืมรหัสผ่านหรือไม่อยู่
9. **เปิดการแจ้งเตือน** ทำข้อ 5 ของ[อัปเดตสคริปต์](#อัปเดตสคริปต์-บทบาทและสิทธิ์--การแจ้งเตือน) (บันทึกหน้าการแจ้งเตือน และให้ทุกคนใส่อีเมลของตัวเอง)

### ใช้รหัสทีมแทนบัญชีผู้ใช้ (แบบเดิม)

ทำได้ แต่ทุกคนใช้รหัสเดียวกัน ไม่มีบทบาท และชื่อผู้บันทึกปลอมได้: ในข้อ 4 ใส่รหัสที่**สุ่มขึ้นมาเอง** ยาวอย่างน้อย 8 ตัวอักษร
(ยาว 12 ตัวขึ้นไปจะดีกว่า) ผสมตัวอักษรกับตัวเลข ไว้ระหว่างเครื่องหมาย `'…'` อย่าใช้ชื่อบริษัท ปี หรือคำที่เดาง่าย
ข้อ 7 เปิดเว็บ จะเข้าแอปได้เลยและพาไปที่การ์ด **แชร์ข้อมูลทีม** ที่มีช่อง **รหัสทีม** รออยู่ ใส่รหัสทีม → **เชื่อมต่อ**
และข้อ 8 กด **คัดลอกลิงก์เชิญทีม** (ลิงก์เว็บ) ส่งให้เพื่อน แล้วบอก**รหัสทีม**แยกต่างหาก
เปลี่ยนมาใช้บัญชีผู้ใช้ภายหลังได้ทุกเมื่อ ([เปิดใช้บัญชีผู้ใช้](#เปิดใช้บัญชีผู้ใช้-หัวหน้าทีม))

## ใช้งาน

- เว็บจะส่งข้อมูลขึ้นชีตทันทีที่แก้ไข และดึงของคนอื่นทุก 30 วินาที (และทุกครั้งที่กลับมาที่หน้าเว็บ)
- มุมขวาบนของเว็บจะมีป้าย **ทีม · ซิงก์แล้ว 14:05** บอกสถานะ ถ้าเน็ตหลุด ข้อมูลที่แก้จะรอในเครื่อง แล้วส่งให้เองเมื่อต่อได้
- ถ้าสองคนแก้คนละช่องของรายการเดียวกัน (เช่น คนหนึ่งแก้เบอร์ อีกคนแก้อีเมลของบริษัทเดียวกัน หรือคนหนึ่งเลื่อนนัด อีกคนติ๊กว่าทำเสร็จ) จะเก็บไว้ทั้งสองค่า
- ถ้าแก้ช่องเดียวกัน (เช่น สถานะการขายของบริษัทเดียวกัน) จะใช้ค่าที่ถึงชีตทีหลัง รวมถึงค่าที่แก้ตอนออฟไลน์ ซึ่งจะถึงชีตเมื่อกลับมาออนไลน์ — ถ้าแก้ตอนออฟไลน์นาน ๆ ให้ตรวจรายการสำคัญอีกครั้งหลังซิงก์
- ชื่อผู้บันทึกมาจากบัญชีที่เข้าสู่ระบบ (ทีมที่ยังใช้รหัสทีม: ให้แต่ละคนเลือก **ฉันคือ** ในแท็บอัปเดตข้อมูล)
- **จดจำฉันในเครื่องนี้** (เลือกไว้ให้แล้ว) อยู่ในระบบได้ 30 วัน และต่ออายุเองเมื่อใช้งาน ถ้าไม่เลือก จะออกจากระบบเองใน 12 ชั่วโมง
  — เครื่องที่ใช้ร่วมกันไม่ต้องเลือก และตอนออกจากระบบให้เลือก **ลบข้อมูลทีมที่เก็บไว้ในเครื่องนี้**
- ถ้าเน็ตหลุดหรือหมดเวลาการเข้าระบบ สิ่งที่แก้ไว้ยังอยู่ในเครื่อง และจะส่งให้หลังเข้าสู่ระบบอีกครั้ง (รายการค้างส่งแยกตามบัญชี
  คนอื่นที่ใช้เครื่องเดียวกันจะไม่ส่งรายการของคุณ)

## การแจ้งเตือนทางอีเมล

สคริปต์ตรวจทุกประมาณ 10 นาที (ตั้งด้วย `setupNotify` หรือ `setup`) แล้วส่งอีเมลจากบัญชี Google ของเจ้าของสคริปต์
ส่วนใบเสนอราคาใหม่หรือที่แก้ ส่งถึงผู้ตรวจ**ทันที**ตอนที่เว็บบันทึกขึ้นชีต (ในคำขอเดียวกัน หลังบันทึกเสร็จ) รอบ 10 นาทีเป็นตัวสำรอง
ผู้รับเห็นชื่อผู้ส่งตามที่ตั้งในหน้าการแจ้งเตือน (ค่าเริ่มต้น **GCC Sales Tracker**)

| เรื่อง | ส่งเมื่อ | ส่งถึง |
| --- | --- | --- |
| ใบเสนอราคาใหม่รอตรวจ (แก้แล้ว: ใบเสนอราคาแก้ไขรอตรวจ พร้อมบอกว่าแก้อะไร) | ทันทีที่แนบหรือแก้ยอด / เลขที่ / วันที่ / ไฟล์ และไฟล์ขึ้น Drive แล้ว (ครั้งละไม่เกิน 3 คน ที่เหลือหรือที่ส่งไม่ทันตามไปในรอบ 10 นาที ถ้าไฟล์ไม่ขึ้น Drive ส่งหลังรอ 30 นาที) | ทุกคนที่มีสิทธิ์ **ตรวจ/อนุมัติใบเสนอราคา** ยกเว้นคนแนบและคนที่แก้ คนใดคนหนึ่งตรวจก็พอ |
| ผลตรวจ (ตรวจแล้ว / ส่งกลับแก้ไข) | 10 นาทีหลังผู้ตรวจกด (ระหว่างนี้ผู้ตรวจกด **เลิกทำ** ได้ ถ้าเลิกทำจะไม่ส่ง) | คนแนบใบเสนอราคา |
| สรุปวันนี้ (งวดเงิน นัดหมาย ใบที่รอตรวจ) | จันทร์–ศุกร์ ตามเวลาที่แต่ละคนเลือก (06:30–09:00) ช้าได้ถึงประมาณ 10 นาที วันไหนไม่มีเรื่องไม่ส่ง | คนที่ได้รับผิดชอบงาน หรือคนที่เลือก **ทั้งทีม** |
| เตือนก่อนนัด 1 ชั่วโมง (ปิดไว้ก่อน เปิดเองได้) | ประมาณ 1 ชั่วโมงก่อนนัดที่ระบุเวลา | ผู้รับผิดชอบบริษัท หรือคนที่เลือก **ทั้งทีม** |
| คำขอสิทธิ์ใหม่ | ภายในประมาณ 10 นาที | ผู้ดูแลระบบทุกคน (ยกเว้นคนขอ) |

- **ส่งเฉพาะอีเมลพนักงานที่ยืนยันรหัส 6 หลักแล้ว** ของบัญชีที่ใช้งานอยู่และบทบาทมีสิทธิ์ **รับอีเมลแจ้งเตือน** ไม่ส่งถึงอีเมลลูกค้าในข้อมูลเด็ดขาด
- **ปุ่มในอีเมลแค่เปิดเว็บ** ต้องเข้าสู่ระบบและกดอนุมัติในเว็บเอง ระบบสแกนลิงก์ของบางบริษัทที่กดลิงก์เองจึงอนุมัติแทนคนไม่ได้
  ลิงก์ใบเสนอราคามีลายเซ็นของสคริปต์ (อายุ 30 วัน) ใช้บอกแค่ว่าการตรวจนั้นมาจากอีเมล ส่วนสิทธิ์ตรวจดูจากบัญชีที่เข้าสู่ระบบเสมอ
- **ผู้รับผิดชอบ** จับคู่กับบัญชีจาก**ชื่อที่แสดง** (ไม่สนตัวพิมพ์เล็ก/ใหญ่และช่องว่าง) งานที่ผู้รับผิดชอบไม่ตรงกับบัญชีใด
  ไม่มีใครได้อีเมล (ยกเว้นคนที่เลือก **ทั้งทีม**) หน้าการแจ้งเตือนในเว็บบอกชื่อที่ไม่ตรง ให้แก้ช่องผู้รับผิดชอบเป็นชื่อบัญชี
- **ใบเสนอราคาที่ต้องตรวจ** คือใบที่นับเป็น Forecast ที่ขั้น QUOTATION ของงานที่ยังไม่ปิด แนบหรือแก้ตั้งแต่วันที่เปิดใช้การแจ้งเตือน
  แก้ยอด เลขที่ วันที่ หรือเปลี่ยนไฟล์ ใบนั้นกลับเป็น "รอตรวจ" และส่งอีเมลใหม่ การอนุมัติไม่เปลี่ยน Forecast
  นำเข้าทีละมาก ๆ (เกิน 20 ใบในรอบเดียว) หรือใบที่ยืนยันยอดไว้นานกว่า 48 ชั่วโมงแล้วเพิ่งซิงก์ จะไม่ส่งอีเมล (ยังขึ้นในกระดิ่งในเว็บ)
- **งวดเงิน** นับตามวันครบกำหนด ยอดตามเอกสาร (รวม VAT) เหมือนหน้า Cashflow รวมงานที่ปิดงานแล้วแต่ยังรับเงินไม่ครบ
  งวดที่ยังไม่กำหนดวันไม่มีการเตือน เลยกำหนดแล้วเตือนซ้ำทุกวัน ทุกวันจันทร์ หรือครั้งเดียว ตามที่ตั้งในหน้าการแจ้งเตือน
- **คนแนบรู้ผลทันที** หลังแนบหรือแก้ใบเสนอราคา ข้อความด้านล่างของเว็บและกระดิ่ง (ใบเสนอราคาของฉัน) บอกว่าส่งให้ผู้ตรวจคนไหนแล้ว
  หรือทำไมยังไม่ได้ส่ง: ไม่มีผู้ตรวจคนอื่น (เช่น ผู้ดูแลระบบเป็นผู้ตรวจคนเดียวแล้วแนบเอง) ผู้ตรวจยังไม่ยืนยันอีเมล ปิดอีเมลไว้
  รอไฟล์ขึ้น Drive โควตาหมด หรือสคริปต์ยังไม่อัปเดต / ยังไม่ได้ Run `setupNotify` ผู้ดูแลระบบดูภาพรวมได้ที่หน้าการแจ้งเตือน การ์ด **ทำไมอีเมลไม่มา**
  ถ้าเปิด **ผู้แนบตรวจใบของตัวเองได้** และไม่มีผู้ตรวจคนอื่น จะบอกว่าคนแนบตรวจใบนั้นเองได้ (ไม่มีอีเมล)
  คนแนบและคนที่แก้ใบนั้นไม่ได้รับอีเมลของใบนั้นเสมอ แม้เปิดให้ตรวจใบของตัวเองได้
- **ปิดการส่งทันที** (ให้ส่งตามรอบ 10 นาทีอย่างเดียว): เจ้าของสคริปต์เพิ่ม Script property `NOTIFY_NOW` = `0`
  (Project Settings → Script properties) ลบออกเพื่อกลับมาส่งทันที
- **แท็บ `notify`** ในไฟล์ชีตนี้คือบันทึกอีเมลที่ส่ง (และเรื่องที่ตัดสินว่าไม่ส่ง) เก็บ 90 วัน สคริปต์ใช้กันส่งซ้ำ **อย่าแก้หรือลบด้วยมือ**
  (`claim` = กำลังส่ง, `retry` = ส่งไม่ทัน รอบ 10 นาทีจะส่งให้, `none:nochk` / `none:nomail` = ไม่มีผู้ตรวจคนอื่น / ผู้ตรวจรับอีเมลไม่ได้,
  `none:self` = ไม่มีผู้ตรวจคนอื่น แต่คนแนบตรวจเองได้) ถ้า lock ไม่ว่างตอนบันทึกผลการส่งทันที ผลจะรอใน Script property `NOTIFY_PEND_…`
  จนรอบ 10 นาทีถัดไปบันทึกแล้วลบเอง
  อีเมลและการตั้งค่าของแต่ละคนเก็บใน Script Properties ไม่อยู่ในชีต `sync` คนในทีมจึงไม่เห็นอีเมลของกันและกัน (ผู้ดูแลระบบเห็น)
- **โควตาอีเมล** Gmail ทั่วไปส่งได้ประมาณวันละ 100 ผู้รับ Google Workspace ประมาณวันละ 1,500 (นับต่อ 24 ชั่วโมง)
  ทีม 7 คนใช้ประมาณวันละ 15–25 ฉบับ หน้าการแจ้งเตือนแสดงว่าวันนี้ส่งไปเท่าไรและเหลือเท่าไร
  เมื่อเหลือไม่เกิน 5 ฉบับ สรุปวันนี้ การเตือนก่อนนัด และรหัสยืนยันอีเมลจะรอ เก็บโควตาที่เหลือไว้ให้ใบเสนอราคาใหม่
  (อีเมลทดสอบรอตั้งแต่เหลือไม่เกิน 10 ฉบับ และแต่ละคนส่งอีเมลทดสอบได้ชั่วโมงละ 3 ครั้ง วันละไม่เกิน 6 ครั้ง)
  อีเมลที่รอไว้จะส่งเองเมื่อโควตากลับมา ไม่หาย
- การตรวจทุก 10 นาทีใช้เวลาประมาณ 2–5 วินาทีต่อรอบ (Gmail ทั่วไปให้สคริปต์ทำงานตามเวลาได้วันละ 90 นาที) และไม่ถือ lock
  ระหว่างส่งอีเมล การซิงก์ของทีมจึงไม่ช้าลง การส่งทันทีก็ไม่ถือ lock ตอนส่ง และส่งเฉพาะช่วง 6 วินาทีแรกของคำขอ
  (คนแนบรอเพิ่มประมาณ 1–3 วินาที)

## แนบเอกสาร (ใบเสนอราคา / ใบแจ้งหนี้)

ในหน้า Sales Tracker แนบไฟล์ใบเสนอราคาและใบแจ้งหนี้ไว้กับรายการขายได้ ไฟล์จะเก็บใน Google Drive **ของคุณ**
(บัญชีที่เป็นเจ้าของสคริปต์) ในโฟลเดอร์ **GCC Sales Tracker — เอกสาร** ซึ่งสคริปต์สร้างให้เอง

- **คนในทีมเปิดไฟล์จากในเว็บได้เลย** เว็บขอไฟล์ผ่านสคริปต์ด้วยรหัสทีม ไม่ต้องแชร์โฟลเดอร์ และคนในทีมไม่ต้องมีสิทธิ์ใน Google Drive ของคุณ
- **ไฟล์ละไม่เกิน 10 MB** รองรับ **PDF** และรูปภาพ **PNG, JPG, WEBP, HEIC** (รูปจาก iPhone)
- **ลบไฟล์แนบในเว็บ** = ย้ายไฟล์ไปถังขยะของ Drive คุณ กู้คืนได้ภายใน 30 วัน
- ชื่อไฟล์ใน Drive ขึ้นต้นด้วยรหัสรายการ เช่น `d123__ใบเสนอราคา QT-001.pdf` เพื่อให้รู้ว่าเป็นของรายการไหน
- **อย่าย้ายไฟล์ออกจากโฟลเดอร์ (รวมถึงเข้าโฟลเดอร์ย่อย)** สคริปต์เปิดให้ทีมเฉพาะไฟล์ที่อยู่ในโฟลเดอร์นี้โดยตรงเท่านั้น
- **ถ้าลบโฟลเดอร์ทิ้ง** ไฟล์ใหม่จะเข้าโฟลเดอร์ใหม่ที่สร้างให้อัตโนมัติ แต่ไฟล์เดิมจะเปิดจากเว็บไม่ได้
  ถ้าลบโดยไม่ตั้งใจ ให้กู้คืนโฟลเดอร์จากถังขยะ**ก่อน**มีคนแนบไฟล์ใหม่ ไฟล์เดิมจะกลับมาเปิดได้
- ไฟล์แนบใช้พื้นที่ Google Drive ของคุณ (บัญชีฟรีมี 15 GB ใช้ร่วมกับ Gmail และ Google Photos)

### อัปเดตสคริปต์ (ทีมที่ตั้งค่าไว้ก่อนมีการแนบเอกสาร)

ถ้าตอนแนบไฟล์ในเว็บขึ้นว่า **"สคริปต์ของทีมยังเป็นเวอร์ชันเก่า"** หัวหน้าทีมต้องอัปเดตโค้ดครั้งเดียว ประมาณ 3 นาที:

1. เปิดไฟล์ Google Sheet ของทีม → **ส่วนขยาย (Extensions) → Apps Script**
2. **เก็บรหัสทีมเดิมไว้ก่อน** คัดลอกบรรทัด `const TEAM_KEY = '…';` ทั้งบรรทัดไปวางพักไว้ (เช่นใน Notepad)
3. ลบโค้ดเดิมทั้งหมด วางโค้ดใหม่จากไฟล์ [`Code.gs`](Code.gs) แล้ว**แทนบรรทัด `const TEAM_KEY = '';` ด้วยบรรทัดที่เก็บไว้** → กด **บันทึก**
   - ต้องเป็นรหัสเดิม ไม่อย่างนั้นทุกเครื่องจะขึ้น "รหัสทีมไม่ถูกต้อง"
4. เลือกฟังก์ชัน `setup` ในช่องข้างปุ่ม **Run** แล้วกด **Run** → Google จะขออนุญาตอีกครั้ง →
   **Review permissions** → เลือกบัญชี → **Advanced** → **Go to … (unsafe)** → **Allow**
   - **ทำไมรอบนี้ Google ขอสิทธิ์ Google Drive** (ขึ้นประมาณว่า *See, edit, create, and delete all of your Google Drive files*)
     เพราะสคริปต์ต้องสร้างโฟลเดอร์และบันทึกไฟล์แนบลง Drive ของคุณ Google ไม่มีตัวเลือกให้สคริปต์ขอสิทธิ์เฉพาะโฟลเดอร์เดียว
     จึงแสดงเป็นสิทธิ์ทั้ง Drive แต่โค้ดจะเปิดหรือลบ**เฉพาะไฟล์ในโฟลเดอร์ GCC Sales Tracker — เอกสาร** (ตรวจทุกครั้งก่อนเปิดหรือลบ)
     ไฟล์อื่นใน Drive ของคุณไม่ถูกแตะ และสิทธิ์นี้เป็นของสคริปต์ที่ทำงานในนามคุณ ไม่ใช่ของคนในทีม
   - สำเร็จเมื่อ **Execution log** ขึ้น "พร้อมใช้งาน: … โฟลเดอร์ "GCC Sales Tracker — เอกสาร" …" และเห็นโฟลเดอร์นี้ใน Google Drive
   - บรรทัด **รหัสตั้งค่าผู้ดูแลระบบ** ที่ขึ้นด้วย ใช้เมื่อพร้อม[เปิดใช้บัญชีผู้ใช้](#เปิดใช้บัญชีผู้ใช้-หัวหน้าทีม) ถ้ายังไม่พร้อม ไม่ต้องทำอะไร (หมดอายุเองใน 24 ชั่วโมง)
5. **Deploy → Manage deployments** → กด ✏️ (**Edit**) → ช่อง **Version** เลือก **New version** → **Deploy**
   - URL เดิมยังใช้ได้ คนในทีมไม่ต้องทำอะไร
   - กดแค่ **บันทึก** ยังไม่พอ เว็บใช้โค้ดเวอร์ชันที่ Deploy ไว้ และอย่ากด **New deployment** (จะได้ URL ใหม่ ที่เว็บไม่รู้จัก)
   - ทำข้อ 4 ก่อนข้อ 5 ถ้า Deploy ไปก่อนแล้ว ให้กลับไปทำข้อ 4 (Run `setup` → Allow) แล้วจะใช้ได้เอง

## เปิดใช้บัญชีผู้ใช้ (หัวหน้าทีม)

สำหรับทีมที่ซิงก์ด้วยรหัสทีมอยู่แล้ว หลังเปิดใช้ ทุกคนเข้าสู่ระบบด้วยบัญชีของตัวเอง และ**รหัสทีมเดิมใช้ไม่ได้อีก**
ประวัติ งานที่ดูแล และตัวกรองของแต่ละคนตามมาครบ เพราะบัญชีใช้**ชื่อที่แสดงเดียวกับชื่อในข้อมูลเดิม** (ไม่มีการแก้ข้อมูลเดิม)

0. **ตรวจว่าเว็บเป็นเวอร์ชันใหม่** ในการ์ด **แชร์ข้อมูลทีม** มีข้อความเรื่องบัญชีผู้ใช้ ถ้ายังไม่มี ใช้รหัสทีมต่อไปตามเดิม
1. **อัปเดตสคริปต์** (ประมาณ 5 นาที — ระหว่างนี้ทุกคนยังซิงก์ด้วยรหัสทีมได้ตามปกติ)
   1. เปิดไฟล์ Google Sheet ของทีม → **ส่วนขยาย (Extensions) → Apps Script**
   2. คัดลอกบรรทัด `const TEAM_KEY = '…';` เดิมทั้งบรรทัดไปวางพักไว้ (เช่นใน Notepad)
   3. ลบโค้ดเดิมทั้งหมด วางโค้ดใหม่จากไฟล์ [`Code.gs`](Code.gs) แล้ว**แทนบรรทัด `const TEAM_KEY = '';` ด้วยบรรทัดที่เก็บไว้** → **บันทึก**
   4. เลือกฟังก์ชัน `setup` → **Run** (ถ้า Google ขออนุญาต ให้ **Allow** แบบตอนติดตั้ง)
   5. คัดลอก **รหัสตั้งค่าผู้ดูแลระบบ: ####-####** จาก **Execution log** (ใช้ได้ครั้งเดียว ภายใน 24 ชั่วโมง)
   6. **Deploy → Manage deployments** → ✏️ (**Edit**) ที่ deployment เดิม → **Version: New version** → **Deploy** — URL เดิมยังใช้ได้
      **อย่ากด New deployment**: จะได้ URL ใหม่ ซึ่งเว็บไม่รู้จัก (เว็บใช้ลิงก์ที่ฝังไว้ ดู[ปัญหาที่พบบ่อย](#ปัญหาที่พบบ่อย))
2. **เปิดใช้ในเว็บ** แท็บ **อัปเดตข้อมูล** → การ์ด **แชร์ข้อมูลทีม** → **เปิดใช้บัญชีผู้ใช้ (หัวหน้าทีม)** → ใส่รหัสตั้งค่า,
   เลือก**ชื่อที่แสดงเดิมของคุณ** (ต้องตรงกับชื่อที่ใช้ในข้อมูลเดิม), ตั้งชื่อผู้ใช้และรหัสผ่าน → **สร้างบัญชีผู้ดูแลและเข้าสู่ระบบ**
   - คุณเป็นผู้ดูแลระบบ และรายการที่แก้ไว้แต่ยังไม่ส่งจะถูกส่งในชื่อของคุณ
   - ภายในประมาณ 30 วินาที เครื่องอื่นในทีมจะขึ้นหน้าเข้าสู่ระบบ "ทีมของคุณเปลี่ยนมาใช้บัญชีผู้ใช้แล้ว…"
     สิ่งที่เขาแก้ไว้แต่ยังไม่ส่งยังอยู่ในเครื่องของเขา และจะส่งหลังเขาเข้าสู่ระบบ
   - แท็บที่เปิดค้างไว้ตั้งแต่ก่อนเว็บอัปเดตจะขึ้น "ซิงก์ไม่สำเร็จ: ทีมเปลี่ยนเป็นระบบเข้าสู่ระบบแล้ว — รีเฟรชหน้าเว็บ (F5)…" ให้กด F5
3. **สร้างบัญชีให้ทุกคนทันที** หน้า **ผู้ใช้และสิทธิ์** → กล่อง **ชื่อในทีมที่ยังไม่มีบัญชี** → **สร้างบัญชี** ทีละคน เลือก[บทบาท](#บทบาทและสิทธิ์)
   แล้วส่งรหัสผ่านชั่วคราวให้เจ้าตัว**ทางแชตส่วนตัว** (เช่น LINE ส่วนตัว ไม่ใช่กลุ่ม) — แนะนำให้มีผู้ดูแลระบบคนที่สองด้วย
4. **สมาชิกเข้าสู่ระบบ** เปิดเว็บ (ไม่ต้องใช้ลิงก์เชิญ) → ชื่อผู้ใช้ + รหัสผ่านชั่วคราว → ตั้งรหัสผ่านของตัวเอง
   รายการที่เขาแก้ไว้ก่อนหน้านี้จะถูกส่งในชื่อบัญชีของเขา
5. (ไม่บังคับ) ลบรหัสทีมออกจากโค้ด (`const TEAM_KEY = '';`) แล้ว Deploy เวอร์ชันใหม่ — หลังข้อ 2 รหัสทีมไม่มีผลอะไรแล้ว

**ย้อนกลับ** วางโค้ดเวอร์ชันเก่ากลับ แล้ว Deploy → Manage deployments → Edit → New version ทุกเครื่องจะกลับไปขอรหัสทีม
รายการที่ค้างส่งไม่หาย ส่วนบัญชีผู้ใช้ยังเก็บอยู่ใน Script Properties (ไม่ถูกใช้ จนกว่าจะวางโค้ดใหม่อีกครั้ง)

## ลืมรหัสผ่าน

- **สมาชิก** ให้ผู้ดูแลระบบตั้งรหัสผ่านชั่วคราวใหม่ให้: **ผู้ใช้และสิทธิ์** → ⋯ ที่ชื่อนั้น → **ตั้งรหัสผ่านชั่วคราวใหม่**
  (เครื่องที่เข้าสู่ระบบไว้ด้วยบัญชีนั้นจะถูกออกจากระบบทันที)
- **ผู้ดูแลระบบ → Run setup แล้วใช้รหัสกู้คืน** (ต้องเป็นเจ้าของไฟล์ Google Sheet หรือคนที่เปิด Apps Script ได้)
  1. เปิดไฟล์ Google Sheet ของทีม → **ส่วนขยาย → Apps Script**
  2. เลือกฟังก์ชัน `setup` แล้วกด **Run**
  3. คัดลอก **รหัสกู้คืนผู้ดูแลระบบ (ใช้เมื่อลืมรหัสผ่าน): ####-####** จาก **Execution log** (ใช้ได้ครั้งเดียว ภายใน 24 ชั่วโมง)
     — บรรทัดก่อนหน้า **ชื่อผู้ใช้ผู้ดูแลระบบ: …** คือชื่อผู้ใช้ของผู้ดูแลระบบทุกคน ถ้าจำชื่อผู้ใช้ของตัวเองไม่ได้ให้ดูตรงนี้
  4. ในเว็บ หน้าเข้าสู่ระบบ → **ลืมรหัสผ่าน?** → **เป็นผู้ดูแลระบบและลืมรหัสผ่าน?** → ใส่รหัสกู้คืน ชื่อผู้ใช้ และรหัสผ่านใหม่
     → **ตั้งรหัสผ่านใหม่และเข้าสู่ระบบ**
  - บัญชีนั้นจะเป็นผู้ดูแลระบบที่ใช้งานได้อีกครั้ง (แม้เคยถูกปิดหรือถูกล็อก) และเครื่องอื่นที่เข้าสู่ระบบไว้จะถูกออกจากระบบ
  - ขึ้นว่า **ไม่พบผู้ใช้นี้** = ชื่อผู้ใช้ไม่มีในทีม (พิมพ์ผิด) แก้ชื่อแล้วกดอีกครั้งด้วยรหัสกู้คืนเดิมได้เลย รหัสยังไม่ถูกใช้
  - ใส่รหัสกู้คืนผิด 5 ครั้ง รหัสนั้นจะใช้ไม่ได้ ให้ Run `setup` ใหม่ — ทุกครั้งที่ Run (รวมถึงตอนอัปเดตโค้ด) จะได้รหัสใหม่
    และรหัสก่อนหน้าใช้ไม่ได้ทันที ถ้าไม่ได้ใช้ ไม่ต้องทำอะไร รหัสหมดอายุเองใน 24 ชั่วโมง

## บทบาทและสิทธิ์

สิทธิ์แยกเป็นรายการย่อย 26 ข้อ (ดู แก้ไข และงานจัดการ) บทบาทคือชุดของสิทธิ์เหล่านี้ ผู้ดูแลระบบสร้างบทบาทเองได้
(เช่น หัวหน้าฝ่ายขาย บัญชี/การเงิน) รวมไม่เกิน 10 บทบาท ที่หน้า **ผู้ใช้และสิทธิ์ → บทบาทและสิทธิ์**

| บทบาทที่มีให้ตั้งแต่แรก | ทำอะไรได้ |
| --- | --- |
| ผู้ดูแลระบบ | ทุกอย่าง รวมถึงจัดการผู้ใช้ บทบาท และอนุมัติคำขอ (แก้บทบาทนี้ไม่ได้) |
| พนักงานขาย | ดูทุกหน้า ยอดเงิน Cashflow และค่าใช้จ่ายของงาน · เพิ่มและแก้ลูกค้า ผู้ติดต่อ ดีล ขั้นตอน นัด แผนชำระ แนบเอกสาร · บันทึกค่าใช้จ่ายเฉพาะงานของตัวเอง · ลบได้เฉพาะบันทึกการติดต่อของตัวเอง · ไม่เห็นค่าคอมมิชชั่น |
| ดูอย่างเดียว | ดูทุกหน้า ยอดเงิน และ Cashflow เปิดไฟล์แนบได้ แก้ไขไม่ได้ · ไม่เห็นค่าใช้จ่ายของงาน |

- **สิทธิ์แก้ไขทุกข้อตรวจที่สคริปต์ของทีม** (ฝั่ง Google) ไม่ใช่แค่ซ่อนปุ่มในเว็บ: รายการที่บัญชีไม่มีสิทธิ์จะไม่ถูกบันทึก
  (เว็บจะใช้ค่าของทีมแทน) ข้อมูลชนิดที่สคริปต์ไม่รู้จัก มีแต่ผู้ดูแลระบบที่บันทึกได้
- **ซ่อนข้อมูลจริง** มีสามข้อ: **ดูยอดเงิน**, **ดูค่าคอมมิชชั่น / สัดส่วนรายได้** และ **ดูค่าใช้จ่ายและกำไรของงาน**
  บัญชีที่ไม่มีสิทธิ์จะไม่ได้รับตัวเลขเหล่านี้จากสคริปต์เลย (รวมยอดเงินที่เว็บเขียนเองในบันทึกขั้นตอนและประวัติดีล และเนื้อหาของรายการค่าใช้จ่าย
  ทั้งประเภท ยอด ผู้บันทึก และเวลา เหลือแค่ key ของรายการเป็นแถวลบ จึงรู้ได้ว่าดีลไหนเคยมีรายการค่าใช้จ่ายกี่รายการ)
  แต่ตัวเลขที่คนพิมพ์เองในหมายเหตุ เช่น "ราคา 350000" ยังเห็นได้ สิทธิ์ดูข้ออื่นเป็นการซ่อนหน้าในเว็บเท่านั้น
- สิทธิ์ **ดีลและขั้นตอน**, **แผนชำระเงินและการรับเงิน**, **บันทึกค่าใช้จ่ายของงาน** และ **ลบบันทึกการติดต่อ** ตั้งเป็น "เฉพาะงานของตัวเอง" ได้:
  งานของตัวเองคือดีลที่ผู้รับผิดชอบสะกดตรงกับชื่อที่แสดงของบัญชี (ทั้งก่อนการส่งครั้งนั้นและตอนบันทึก) และบันทึกที่บัญชีนั้นเขียนเอง
  บัญชีที่แก้ **ดีลและขั้นตอน** ได้ทุกดีล เปลี่ยนผู้รับผิดชอบของดีลใดก็ได้ จึงทำให้ดีลนั้นเป็นงานของตัวเองได้ (ทุกคนเห็นผู้รับผิดชอบที่เปลี่ยน)
  สคริปต์กันแค่การเปลี่ยนผู้รับผิดชอบ บันทึก แล้วเปลี่ยนกลับในการส่งครั้งเดียว ถ้าต้องการให้ "เฉพาะงานของตัวเอง" ของแผนชำระเงินหรือค่าใช้จ่าย
  จำกัดได้จริง ให้ตั้ง **ดีลและขั้นตอน** เป็นเฉพาะงานของตัวเองด้วย
- **ขอสิทธิ์เพิ่ม**: ทุกบัญชี (ยกเว้นผู้ดูแลระบบ) ขอเปลี่ยนบทบาทหรือขอสิทธิ์บางข้อได้ พร้อมเหตุผล และวันสิ้นสุดถ้าต้องการ
  ผู้ดูแลระบบเห็นตัวเลขที่เมนู ผู้ใช้และสิทธิ์ แล้วอนุมัติหรือไม่อนุมัติ อนุมัติคำขอของตัวเองไม่ได้ และขอเป็นผู้ดูแลระบบผ่านคำขอไม่ได้
  ผู้ดูแลระบบให้สิทธิ์เพิ่มเฉพาะคนได้เองโดยไม่ต้องรอคำขอ สิทธิ์ที่มีวันสิ้นสุดใช้ได้ถึงสิ้นวันนั้น (เวลาไทย)
- การเปลี่ยนบทบาท สิทธิ์ คำขอ และสิทธิ์เพิ่ม ถูกบันทึกในแท็บ **audit** ของไฟล์ชีตนี้ (เก็บ 12 เดือน)
- ต้องมีผู้ดูแลระบบที่ใช้งานได้อย่างน้อย 1 คน และผู้ดูแลระบบเปลี่ยนบทบาทหรือปิดบัญชีของตัวเองไม่ได้
- เปลี่ยนบทบาท สิทธิ์ หรือปิดบัญชีแล้ว มีผลกับคำขอถัดไปของบัญชีนั้นทันที ไม่ต้องรอให้เขาเข้าสู่ระบบใหม่
- **ชื่อที่แสดง** คือชื่อที่ใช้ในข้อมูล (ผู้รับผิดชอบ ผู้บันทึก ที่ฉันดูแล) แก้ได้เฉพาะก่อนบัญชีนั้นเข้าสู่ระบบครั้งแรก
- ใส่รหัสผ่านผิด 5 ครั้งใน 15 นาที ชื่อผู้ใช้นั้นจะถูกพัก 15 นาที (ผู้ดูแลระบบกด **ปลดล็อก** ได้)
- ทีมหนึ่งมีได้ไม่เกิน 25 บัญชี (นับรวมบัญชีที่ปิดการใช้งาน)

### ค่าใช้จ่ายของงาน (เงินออก)

ต่อดีล บันทึกว่าจ่ายเงินออกไปเท่าไหร่ เช่น "เงินเข้า 100,000 · ค่าใช้จ่าย 35,000 · คงเหลือ 65,000" หน้าบันทึกจะมาในเว็บรุ่นถัดไป
สคริปต์รุ่นนี้เก็บและตรวจสิทธิ์ให้แล้ว:

- **ประเภทค่าใช้จ่ายพิมพ์เองได้** (เช่น ผู้รับเหมาหรือที่ปรึกษาภายนอก ค่าเดินทาง ค่าธรรมเนียม TGO ค่าแล็บ) ไม่มีรายการตายตัว ไม่ต้องตั้งค่าก่อน
- **ใครเห็น / ใครบันทึก** ผู้ดูแลระบบเลือกในบทบาทได้สองข้อ: **ดูค่าใช้จ่ายและกำไรของงาน** (ต้องมีดูยอดเงิน) และ **บันทึกค่าใช้จ่ายของงาน**
  (ต้องมีดูค่าใช้จ่าย ตั้งเป็นเฉพาะงานของตัวเองได้ = ดีลที่ตัวเองเป็นผู้รับผิดชอบ) ตั้งต้น: ผู้ดูแลระบบทั้งหมด · พนักงานขายเห็นทุกงาน
  บันทึกเฉพาะงานของตัวเอง · ดูอย่างเดียวไม่เห็น
- ผู้บันทึกและเวลาบันทึก สคริปต์เป็นคนเขียนเอง (ชื่อบัญชีและเวลาของเซิร์ฟเวอร์) ยกเว้นผู้ดูแลระบบที่กู้ข้อมูล ค่าใช้จ่ายที่ใครบันทึกบนดีลของคนอื่น
  จึงเห็นชื่อผู้บันทึกเสมอ (พนักงานขายแก้ดีลได้ทุกดีล จึงเปลี่ยนผู้รับผิดชอบเป็นตัวเองแล้วบันทึกได้ ดูหัวข้อ "เฉพาะงานของตัวเอง" ด้านบน)
- **บัญชีตรวจทั้งเงินเข้าและเงินออก** ผู้มีสิทธิ์ **ตรวจยืนยันรับเงิน (บัญชี)** ตรวจค่าใช้จ่ายที่จ่ายแล้ว ส่งกลับแก้ไข และปิดเดือนฝั่งเงินออกได้
  แบบเดียวกับเงินเข้า (ผู้ตรวจควรมีสิทธิ์ดูค่าใช้จ่ายด้วย ไม่อย่างนั้นจะไม่เห็นรายการ)
- บิลหรือใบเสร็จของค่าใช้จ่ายแนบได้ด้วยสิทธิ์บันทึกค่าใช้จ่ายอย่างเดียว (ไม่ต้องมีสิทธิ์แนบเอกสาร) เปิดดูไฟล์ยังต้องมีสิทธิ์เปิดเอกสารแนบ
  บัญชีที่บันทึกได้เฉพาะงานของตัวเอง (และไม่มีสิทธิ์แนบเอกสาร) ย้ายบิลไปถังขยะได้เฉพาะบิลของค่าใช้จ่ายในดีลของตัวเอง
- ลบดีลแล้ว ค่าใช้จ่ายของดีลนั้นถูกลบตาม (แม้คนลบจะไม่เห็นค่าใช้จ่าย) ส่วนการตรวจของบัญชียังอยู่ ให้บัญชีเห็นว่ารายการที่ตรวจแล้วหายไป

ระเบียนในชีต `sync` (สำหรับผู้พัฒนา):

| key | ค่า | เขียน / ลบ |
| --- | --- | --- |

- บัญชีที่ไม่มี `view.exp` (หรือไม่มี `view.money`) ได้ทั้งสี่ชนิดเป็นแถวลบ (`v: null, del: true, by: '', at: ''`) ในตำแหน่งเดิม
  key และ seq ยังอยู่ (เครื่องที่เคยมีรายการนั้นจะลบทิ้งได้) แต่ไม่มีเนื้อหา ผู้บันทึก หรือเวลา
- เฉพาะงานของตัวเองของ `dexp/` (และ `dstep/` `dact/` `dpay/`) ดูผู้รับผิดชอบของดีลทั้งตามที่อยู่ในชีตก่อน `push` นั้นและ ณ op นั้น
  (ดีลที่ `push` นั้นสร้างเองนับตั้งแต่ op ที่สร้าง) การเปลี่ยนผู้รับผิดชอบให้ตัวเองใน `push` เดียวกันจึงใช้ไม่ได้ (op นั้นอยู่ใน `denied`)
- `delfile` ด้วย `edit.exp` แบบ `own` (ไม่มี `docs.up`): ได้เฉพาะไฟล์ `exp_<expId>__…` ที่ทุก `dexp/<dealId>/<expId>` ของ expId นั้น (ยังอยู่หรือลบแล้ว)
  และทุก `dexp/` ที่ `file.id` เป็นไฟล์นี้ อยู่ในดีลที่บัญชีเป็นผู้รับผิดชอบ (ดีลที่ถูกลบดูผู้รับผิดชอบก่อนลบ) ต้องมีอย่างน้อยหนึ่งรายการ
  บิลที่ยังไม่ผูกกับค่าใช้จ่ายใด ผู้ที่มี `edit.exp` ทุกงานหรือ `docs.up` เป็นคนย้ายไปถังขยะ
- `pull` ที่ไม่มี `xp: 1` (เว็บรุ่นก่อนค่าใช้จ่าย รวมทีมที่ใช้รหัสทีม) ได้ `dchk/<dealId>/exp.*` เป็นแถวลบ เพราะเว็บรุ่นนั้นจะอ่านเป็นการตรวจเงินเข้าที่ถูกยกเลิก
  ส่วน `dexp/` และ `mclose/<YYYY-MM>/out` เว็บรุ่นนั้นข้ามเองอยู่แล้ว
- **ช่องที่ยังเปิดอยู่ (แก้ในการอัปเดตสคริปต์ครั้งถัดไป):** สคริปต์รุ่นนี้รับ `dchk/<dealId>/exp.*`, `mclose/<YYYY-MM>/out` และ `dlog/exp.*`
  จากบัญชีที่มี `pay.check` แม้ไม่มี `view.exp` (ตรวจด้วย simulator แล้ว: `push` ทั้งสามชนิดได้ `denied: []`) เว็บไม่ส่งระเบียนเหล่านี้จากบัญชีแบบนั้น
  (ไม่เห็นส่วนเงินออกเลย และเว็บปฏิเสธเองด้วย `expCheckBlock` = `cap`) แต่คนที่แก้โค้ดในเครื่องเองยังส่งตรงไปที่สคริปต์ได้
  ระหว่างนี้ให้บทบาทที่มี **ตรวจยืนยันรับเงิน (บัญชี)** มี **ดูค่าใช้จ่ายและกำไรของงาน** ด้วย ·
  ครั้งถัดไป: `KEY_CAP` ของ `dchk/*/exp.`, `mclose/*/out` และ `dlog/exp.` (ทาง `pay.check`) ต้องมี `view.exp` ด้วย
- `role_save` ที่ `c` ไม่มี `view.exp` / `edit.exp` (เว็บรุ่นก่อนค่าใช้จ่าย) คงค่าเดิมของบทบาทไว้ เว็บรุ่นใหม่ส่ง `0` เมื่อปิด
- เว็บรุ่นใหม่ดูว่าสคริปต์รู้จักสองข้อนี้หรือไม่จาก `roles.admin.c` (ผู้ดูแลระบบมีทุกข้อที่สคริปต์มี) ถ้าไม่รู้จัก (สคริปต์ v4 ก่อนค่าใช้จ่าย)
  หน้าแก้บทบาท ให้สิทธิ์เพิ่ม ขอสิทธิ์ และสิทธิ์ของฉัน จะไม่แสดงสองข้อนี้
- ไม่ต้องเปลี่ยน protocol (ยังเป็น v4) และไม่ต้องขอสิทธิ์ Google ใหม่

## เข้าสู่ระบบช่วยอะไร / ไม่ช่วยอะไร

**ช่วย**
- ข้อมูลทีมในไฟล์ Google Sheet และไฟล์แนบใน Drive เปิดได้เฉพาะคนที่เข้าสู่ระบบ และแก้ได้ตามสิทธิ์ของบัญชี
- คอลัมน์ `by` ในชีต (ใครแก้) สคริปต์เป็นคนเขียนชื่อบัญชีเอง ปลอมไม่ได้ ชื่อผู้บันทึกในบันทึกการติดต่อ และชื่อกับเวลาของการตรวจรับเงินก็เช่นกัน
- รหัสผ่านไม่ออกจากเบราว์เซอร์ เว็บแปลงรหัสผ่านก่อนส่ง และสคริปต์เก็บเฉพาะค่าที่แปลงซ้ำอีกชั้น ไม่มีใครอ่านรหัสผ่านจริงได้

**ไม่ช่วย**
- ฐานข้อมูลบริษัท (ทะเบียน) และโค้ดของเว็บ ซึ่งเป็นข้อมูลสาธารณะอยู่แล้ว
- ข้อมูลทีมที่ซิงก์ลงเบราว์เซอร์แล้ว ยังอ่านได้บนเครื่องนั้น (เช่นผ่าน DevTools) จนกว่าจะออกจากระบบแบบเลือก **ลบข้อมูลทีมที่เก็บไว้ในเครื่องนี้**
- การเข้าสู่ระบบที่ถูกคัดลอกออกจากเครื่อง ใช้ได้จนหมดอายุ หรือจนกด **ออกจากระบบทุกเครื่อง** (หรือเปลี่ยนรหัสผ่าน)
- คนที่แก้ไขไฟล์ Google Sheet หรือโปรเจกต์ Apps Script ได้ อ่านค่าที่ใช้ตรวจรหัสผ่าน พิมพ์รหัสกู้คืน และแก้แถวในชีตได้ทั้งหมด

**ข้อปฏิบัติ**
- **อย่าแชร์ไฟล์ Google Sheet ให้ใครเป็นผู้แก้ไข (Editor)** คนในทีมไม่ต้องมีสิทธิ์ในไฟล์เลย ใช้งานผ่านเว็บอย่างเดียว
- **ส่งรหัสผ่านชั่วคราวให้ทีละคนทางแชตส่วนตัว** ไม่ใช่ในกลุ่ม และให้เจ้าตัวตั้งรหัสผ่านใหม่ทันที
- **อัปเดตสคริปต์ด้วย Deploy → Manage deployments → ✏️ Edit → New version เสมอ** อย่ากด **New deployment** (URL จะเปลี่ยน แต่เว็บยังใช้ลิงก์เดิมที่ฝังไว้)
- เครื่องที่ใช้ร่วมกัน: ไม่ต้องเลือก **จดจำฉัน** และตอนออกจากระบบให้เลือกลบข้อมูลทีมในเครื่อง
- พนักงานลาออก: **ปิดการใช้งาน** บัญชี (ข้อมูลที่เขาบันทึกยังอยู่ครบ และเขาจะถูกออกจากระบบทุกเครื่อง)

## ข้อควรรู้

- **อย่าแก้ข้อมูลในชีต `sync` ด้วยมือ** แต่ละแถวคือการเปลี่ยนแปลงหนึ่งครั้ง (seq, k, v, del, by, at) ระบบจะลบแถวเก่าที่ถูกแทนที่แล้วให้เองเมื่อชีตยาวขึ้น
- **เปลี่ยนรหัสทีม** (ทีมที่ยังใช้รหัสทีม) แก้ `TEAM_KEY` แล้ว Deploy เวอร์ชันใหม่ (ดูด้านล่าง) ทุกเครื่องจะขึ้นว่า "รหัสทีมไม่ถูกต้อง"
  พร้อมช่อง **รหัสทีมใหม่** ใส่รหัสใหม่แล้วกด **ใช้รหัสใหม่** ข้อมูลที่ค้างส่งจะถูกส่งต่อให้ ไม่ต้องยกเลิกการเชื่อมต่อ
- **แก้โค้ดสคริปต์ภายหลัง** ใช้ **Deploy → Manage deployments → ✏️ Edit → Version: New version → Deploy** URL จะเหมือนเดิม
  (ถ้ากด New deployment จะได้ URL ใหม่ ที่เว็บไม่รู้จัก ดู[ปัญหาที่พบบ่อย](#ปัญหาที่พบบ่อย))
- **ย้ายไปลิงก์ใหม่** เว็บใช้ลิงก์ที่ฝังไว้ ให้ผู้พัฒนาเปลี่ยนลิงก์ในเว็บ เมื่อเปิดเว็บเวอร์ชันใหม่ แต่ละเครื่องจะย้ายมาลิงก์ใหม่เอง
  พร้อมรายการที่ค้างส่ง (สคริปต์เดิม ชีตเดิม คนที่เข้าสู่ระบบไว้ไม่ต้องเข้าสู่ระบบใหม่)
  — เว็บที่ไม่มีลิงก์ฝังไว้: กด **ยกเลิกการเชื่อมต่อ** แล้วเชื่อมใหม่ด้วยลิงก์เชิญอันใหม่ รายการที่ยังส่งไม่ได้จะตามไปส่งที่ลิงก์ใหม่
- **เปิดหลายแท็บ** ทุกแท็บในเบราว์เซอร์เดียวกันใช้การเชื่อมต่อเดียวกัน เชื่อมต่อ/ยกเลิก/เปลี่ยนรหัสในแท็บหนึ่ง แท็บอื่นจะทำตาม
- **ความปลอดภัย** ดู[เข้าสู่ระบบช่วยอะไร / ไม่ช่วยอะไร](#เข้าสู่ระบบช่วยอะไร--ไม่ช่วยอะไร) ทีมที่ยังใช้รหัสทีม: คนที่มีทั้ง URL และรหัสทีม
  อ่านและแก้ข้อมูลทีมได้ รวมถึงเปิด แนบ และลบไฟล์แนบ ส่งรหัสทีมให้เฉพาะคนในทีม
  ส่วนไฟล์ Google Sheet และโฟลเดอร์ใน Drive ยังเปิดได้เฉพาะคุณ
- **โควตา** สคริปต์อ่าน/เขียนค่าที่บันทึกไว้ (Properties) ได้วันละ 50,000 ครั้งสำหรับบัญชี Gmail ทั่วไป (Google Workspace 500,000 ครั้ง)
  การเช็กว่ามีของใหม่ทุก 30 วินาทีไม่ใช้โควตานี้ (ใช้ cache ของสคริปต์ รวมถึงการตรวจบัญชีผู้ใช้ บทบาท และคำขอในแต่ละคำขอ)
  การแจ้งเตือนใช้ประมาณวันละ 300 ครั้ง (อ่านและเขียนรอบละ 2 ครั้ง ทุก 10 นาที)
  จึงพอสำหรับทีมประมาณ 10 คนที่เปิดเว็บทั้งวัน การเข้าสู่ระบบใช้โควตาเล็กน้อยเฉพาะตอนเข้าสู่ระบบ
  ถ้าโควตาหมด การซิงก์จะหยุดถึงวันถัดไป แต่สิ่งที่แก้ยังเก็บอยู่ในเครื่อง และจะส่งเองเมื่อกลับมาใช้ได้
  โควตาอีเมลดูหัวข้อ[การแจ้งเตือนทางอีเมล](#การแจ้งเตือนทางอีเมล)
- **นำเข้าไฟล์สำรองตอนเชื่อมต่ออยู่** จะเพิ่มเฉพาะรายการที่ทีมยังไม่มี รายการที่ทีมมีแล้ว (หรือลบไปแล้ว) ใช้ค่าของทีม
- **บริษัทที่ดึงเพิ่มจากเว็บ TGO** (รหัส TGO-…) เป็นของแต่ละเครื่อง ดาว สถานะ นัด และบันทึกของบริษัทกลุ่มนี้จึงไม่แชร์
- **สิทธิ์ของสคริปต์** (รายการเต็มอยู่ใน [`appsscript.json`](appsscript.json))
  - ชีต: เฉพาะไฟล์นี้ (`@OnlyCurrentDoc`) ไม่ได้แตะ Google Sheet ไฟล์อื่นของคุณ ใช้แท็บ `sync` (ข้อมูลทีม) `audit` (ใครเปลี่ยนสิทธิ์)
    และ `notify` (อีเมลที่ส่ง)
  - Drive: ใช้เฉพาะโฟลเดอร์ **GCC Sales Tracker — เอกสาร** สำหรับไฟล์แนบ (ดูหัวข้อแนบเอกสาร)
  - ส่งอีเมลในนามคุณ: เฉพาะการแจ้งเตือนถึงอีเมลพนักงานที่ยืนยันแล้ว และรหัสยืนยันถึงอีเมลที่เพิ่งใส่ ไม่อ่านกล่องจดหมายของคุณ
  - ทำงานเมื่อคุณไม่ได้เปิดอยู่: การตั้งเวลา `notifyTick` ทุก 10 นาทีเท่านั้น (ดูได้ที่เมนู **ทริกเกอร์ (Triggers ⏰)** ใน Apps Script)

## ปัญหาที่พบบ่อย

| ข้อความในเว็บ | วิธีแก้ |
| --- | --- |
| เชื่อมต่อไม่ได้ — ตรวจว่าใช้ลิงก์ … /exec … Anyone | ตอน Deploy ตั้ง **Who has access** เป็น **Anyone** หรือยัง และใช้ลิงก์ที่ลงท้ายด้วย `/exec` |
| เชื่อมต่อทีมไม่ได้: ติดต่อ Google Sheet ของทีมไม่ได้ — ตรวจว่าเครื่องต่ออินเทอร์เน็ตอยู่ … (หน้าแรกของเว็บ) | ตรวจอินเทอร์เน็ต แล้วกด **ลองอีกครั้ง** ถ้าขึ้นทุกเครื่อง หัวหน้าทีมตรวจว่าสคริปต์ยัง Deploy อยู่ และ **Who has access** เป็น **Anyone** |
| ได้ลิงก์ Web app ใหม่ (กด New deployment) | เว็บใช้ลิงก์ที่ฝังไว้ในเว็บ ไม่ใช่ลิงก์ใหม่ ทางแก้เลือกอย่างใดอย่างหนึ่ง: แจ้งลิงก์ใหม่ให้ผู้พัฒนาเปลี่ยนในเว็บ (แต่ละเครื่องจะย้ายไปลิงก์ใหม่เองพร้อมรายการที่ค้างส่ง) หรือ **Manage deployments** → ✏️ **Edit** ที่ deployment **เดิม** → **Version: New version** → **Deploy** แล้วกด **Archive** deployment ที่เกินมา |
| สคริปต์ยังไม่มีรหัสทีม | สคริปต์ยังไม่มีบัญชีผู้ใช้และไม่มีรหัสทีม: หัวหน้าทีม[สร้างบัญชีผู้ดูแลระบบ](#ขั้นตอน-ทีมใหม่) (ข้อ 7) หรือถ้าจะใช้รหัสทีม ใส่ `TEAM_KEY` (อย่างน้อย 8 ตัว) แล้ว **Deploy → Manage deployments → ✏️ Edit → New version** |
| รหัสทีมไม่ถูกต้อง | ตรวจรหัสกับหัวหน้าทีม (ตัวพิมพ์เล็ก/ใหญ่ต้องตรงกัน) |
| ชีตไม่ตอบกลับ / เชื่อมต่อชีตไม่ได้ชั่วคราว | ระหว่างใช้งานจะหายเอง (เว็บลองใหม่ทุก 30 วินาที) ถ้าขึ้นตอนกด **เชื่อมต่อ** หรือ **ใช้รหัสใหม่** ให้กดอีกครั้ง ถ้าเป็นนาน ตรวจว่าเปิดเว็บ Google ได้ และสคริปต์ยัง Deploy อยู่ |
| ไม่เห็นชีต `sync` หลังกด Run | ช่องข้างปุ่ม Run ต้องเป็น `setup` (ไม่ใช่ `doGet`) แล้วดูข้อความใน **Execution log** ด้านล่าง |
| Execution log: Cannot read properties of null | สคริปต์ไม่ได้สร้างจากไฟล์ชีต ให้เปิดไฟล์ Google Sheet → **ส่วนขยาย → Apps Script** แล้ววางโค้ดที่นั่น |
| Execution log: TEAM_KEY ต้องยาวอย่างน้อย 8 ตัวอักษร | รหัสทีมสั้นเกินไป ใส่รหัสยาว 8 ตัวขึ้นไป หรือเว้นว่าง (`''`) ถ้าใช้บัญชีผู้ใช้อย่างเดียว แล้วกด **บันทึก** |
| ลิงก์ต้องเป็น Web app ของ Google Apps Script | วางลิงก์ Web app (`https://script.google.com/macros/s/…/exec`) ไม่ใช่ลิงก์ของไฟล์ Google Sheet |
| สคริปต์ของทีมยังเป็นเวอร์ชันเก่า — อัปเดต Code.gs แล้ว Deploy เวอร์ชันใหม่ | ทำตาม [อัปเดตสคริปต์](#อัปเดตสคริปต์-ทีมที่ตั้งค่าไว้ก่อนมีการแนบเอกสาร) ข้อ 1–5 ถ้าทำแล้วยังขึ้น ตรวจว่าตอนท้ายใช้ **Manage deployments → ✏️ Edit → Version: New version → Deploy** (กดแค่บันทึกยังไม่พอ) |
| ไฟล์ที่แนบ … ไฟล์ยังเก็บอยู่ในเบราว์เซอร์นี้ ยังไม่ขึ้น Drive ของทีม (หน้า Sales Tracker) | ลิงก์ที่เว็บใช้ยังเรียกสคริปต์รุ่นที่เก็บไฟล์ไม่ได้ ไฟล์ปลอดภัยในเบราว์เซอร์ของคนที่แนบ หัวหน้าทีมวาง Code.gs ล่าสุด แล้ว **การทำให้ใช้งานได้ (Deploy) → จัดการการทำให้ใช้งานได้ (Manage deployments) → ✏️ แก้ไข (Edit) ที่รายการที่ลิงก์ตรงกับเว็บ → เวอร์ชัน: เวอร์ชันใหม่ (New version) → ทำให้ใช้งานได้ (Deploy)** ไฟล์จะขึ้นเองภายใน 2 นาทีขณะคนที่แนบเปิดเว็บไว้ หรือทันทีเมื่อกลับมาที่แท็บหรือรีเฟรชหน้าเว็บ ระหว่างนี้คนที่แนบอย่าล้างข้อมูลเบราว์เซอร์ อย่าลบหรือเปลี่ยนไฟล์ และถ้าออกจากระบบ อย่าเลือก “ลบรายการที่ยังไม่ได้ส่งด้วย” |
| อัปโหลดเอกสารขึ้น Drive ไม่สำเร็จ: ลิงก์ของทีมตอบกลับไม่ใช่คำตอบของสคริปต์ … | ลิงก์ไปไม่ถึงสคริปต์ (คำขอถูกเปลี่ยนทางระหว่างทาง) ตรวจว่าเว็บใช้ลิงก์ Web app ที่ลงท้ายด้วย `/exec` และ **Who has access** เป็น **Anyone** ไฟล์ยังอยู่ในเครื่องที่แนบ เว็บจะลองใหม่เอง |
| หัวหน้าทีมยังไม่ได้อนุญาตให้สคริปต์ใช้ Google Drive | หัวหน้าทีมเปิด Apps Script เลือก `setup` → **Run** → **Allow** (อัปเดตสคริปต์ ข้อ 4) |
| ลิงก์ไม่ถูกต้อง หรือสคริปต์ยังไม่ได้ Deploy … (ขึ้นทุกเครื่องทันทีหลังอัปเดตโค้ด) | มักเป็นเพราะยังไม่ได้กด Run `setup` → **Allow** หลังวางโค้ดใหม่ ทำ อัปเดตสคริปต์ ข้อ 4 |
| ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง | ตรวจตัวสะกดของชื่อผู้ใช้ และดูว่าแป้นพิมพ์เป็นภาษาไทยหรือเปิด Caps Lock อยู่หรือไม่ ถ้าลืมรหัสผ่าน ให้ผู้ดูแลระบบตั้งรหัสผ่านชั่วคราวใหม่ ([ลืมรหัสผ่าน](#ลืมรหัสผ่าน)) |
| ใส่รหัสผ่านผิดหลายครั้ง ลองใหม่ได้เวลา … น. | ชื่อผู้ใช้นี้ถูกพัก 15 นาที รอจนถึงเวลานั้น หรือให้ผู้ดูแลระบบกด **ปลดล็อก** (ผู้ใช้และสิทธิ์ → ⋯) |

## สำหรับนักพัฒนา

- `Code.gs` — สคริปต์ฝั่ง Google (protocol อธิบายไว้ต้นไฟล์)
- `sim.mjs` — รัน `Code.gs` ตัวจริงใน Node ด้วย Google services จำลอง (รวม DriveApp / Utilities) ใช้ในชุดทดสอบ
  (`app/src/lib/teamSync.test.ts`, `app/src/lib/teamFiles.test.ts`)
- `dev-server.mjs` — เซิร์ฟเวอร์ทดสอบในเครื่อง: `node team-sync/dev-server.mjs [port] [teamKey] [--kdf N]`
  (ไฟล์แนบและบัญชีเก็บในหน่วยความจำ หายเมื่อปิดเซิร์ฟเวอร์) ตอนเริ่มจะรัน `setup` และพิมพ์ `owner code: ####-####`
  - บัญชีผู้ใช้: `node team-sync/dev-server.mjs 8787 '' --kdf 1000` → วาง URL `http://localhost:8787` ในเว็บ
    → หน้าเปิดใช้บัญชีผู้ใช้ → ใส่ owner code ที่พิมพ์ไว้ (`--kdf` = จำนวนรอบ PBKDF2 ค่าเริ่มต้น 1000 ให้เข้าสู่ระบบเร็วตอนพัฒนา
    ของจริงใช้ 200000 และเว็บที่ build แบบ production ไม่ยอมรับต่ำกว่า 100000 — ใช้ `--kdf 100000` กับเว็บที่ build แล้ว)
  - รหัสทีม (แบบเดิม): `node team-sync/dev-server.mjs 8787 test-key-123` แล้วเชื่อมต่อด้วยรหัส `test-key-123`
- **ลิงก์ของทีมที่ฝังในเว็บ** อยู่ที่ `HOME_TEAM_URL` ใน `app/src/lib/constants.ts` ใช้กับ build แบบ production
  ตั้ง `VITE_TEAM_URL` ตอน build เพื่อใช้ลิงก์อื่น: `VITE_TEAM_URL=http://localhost:8787` (dev-server ด้านบน ไม่ต้องวาง URL)
  หรือ `VITE_TEAM_URL=` (ว่าง = ไม่มีทีมฝัง แบบเดิม: ใช้แบบไม่เชื่อมทีม หรือวางลิงก์เองได้) — `vite dev` และชุดทดสอบไม่มีลิงก์ฝังเว้นแต่ตั้งไว้
  เปลี่ยนลิงก์ฝังแล้ว เครื่องที่เก็บลิงก์เดิมจะย้ายมาลิงก์ใหม่เองตอนเปิดเว็บ (ทดสอบใน `app/src/lib/auth.engine.test.ts`)
